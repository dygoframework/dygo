# Dygo Academy (example)

A small course platform backend, built to dogfood Dygo for v1.0. It was
scaffolded with the CLI and then given real behaviour:

```sh
dygo new academy -t modular
dygo g resource courses -fields "title:string summary:text? level:string price:float published:bool"
dygo g resource lessons -fields "courseId:int title:string body:text position:int"
dygo g security                 # was dygo g auth until phase 9
dygo g resource enrollments -fields "courseId:int userId:int"   # then rewritten by hand
dygo g listener notify
dygo g job welcome-email
```

## What it does

| Route | Who | Does |
|---|---|---|
| `POST /auth/register`, `/auth/login`, `/auth/refresh`, `/auth/logout`, `GET /auth/me` | anyone (me: signed in) | accounts, access and refresh tokens (generated by `dygo g security`) |
| `GET /courses`, `GET /courses/{id}` | anyone | the public catalogue, opened in `security/rules.go` |
| `POST`, `PATCH`, `DELETE /courses...` | admin | manage courses (`security.Roles("admin")`) |
| `GET`, `POST`, `DELETE /enrollments...` | signed in | enroll in a published course, list and drop your own (locked by default: no rule opens it) |
| `/lessons...` | read: anyone, write: admin | lessons |
| `/health/live`, `/health/ready`, `/docs` | anyone | health checks and the OpenAPI UI |

Enrolling emits an `enrollments.Enrolled` event. The `notify` listener turns it
into a `welcome-email` job on the in-memory queue, and the `welcomeemail`
processor sends it in the background, so a slow mail server never slows the
request down.

Security is deny by default: every route needs a token unless
`internal/modules/security/rules.go` or `security.Public()` opens it (see the
[security recipe](../../docs/recipes/security.md)). The first admin comes from
`AUTH_ADMIN_EMAIL` and `AUTH_ADMIN_PASSWORD` (`security/admin.go`, added by
hand with its two settings in `security/config.go`). Tests sign in with `securitytest.Setup(t)` and
`.With(securitytest.Admin())` instead of registering and logging in;
`academy_test.go` also walks through refresh, reuse and logout.

## Run it

```sh
cp .env.example .env
AUTH_ADMIN_EMAIL=admin@academy.test AUTH_ADMIN_PASSWORD=change-me go run .
go test -race ./...      # academy_test.go is the whole story end to end
dygo check && dygo routes
```

Storage is in memory. The [SQL recipe](../../docs/recipes/sql.md) shows how
to swap a service's map for Postgres.
